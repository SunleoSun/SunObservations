# Documentation and downstream fixtures

certifications/documentation_certification.rs compiles canonical skill and README Rust examples together in one downstream library fixture. README modules preserve hidden Rustdoc lines, item/statement forms, explicit tests, and no_run type checking. Runnable README tests execute in individually filtered child processes so global runtime configuration cannot leak between examples. The harness verifies child success and exactly one executed test; returned errors, failing children, missing filters, and a panicking compile-only example are independent controls. Unsupported API bindings remain compile-failure controls. Structural documentation checks separately own receiver/type/arity, API ownership, DSL completeness, and canonical/mirror equality. Focused authoring fixtures require executable implementations of the intentionally portable extension traits and positional tuple-enum payload syntax inside canonical skills. Signature-removal mutations protect fixture completeness; downstream compile-failure controls protect fallible violation vectors, provenance formatter output, borrowed/shared sink delivery, and borrowed persisted versus owned transient Observation text. Trait receivers are not client call arguments. Public compiler/classifier methods remain outside the portable API. The repository-root README is the canonical handbook and crates/sun-observations/README.md is its full publishable mirror with repository-relative img/, docs/, and crates/ links rebased from the package directory; the derive companion owns a separate short README.

The portable Observation grammar includes unit-returning best-effort observe! and fallible try_observe!. Authoring mutation controls require both alternatives, their distinct return contracts, and preservation of capture emission-error accounting. The renamed-dependency downstream fixture uses both macros under deny(unused_must_use), including unit-expression and trailing-comma forms.

Documentation and downstream derive fixtures reuse the surrounding Cargo target directory rather than rebuilding dependencies in each temporary project. Downstream invalid Observation declarations compile together, but each expected diagnostic must have a primary span inside its own declaration.

The skill installation certification uses a persistent skill-install target below the shared target directory, not the live workspace target itself. Cargo install may replace its debug CLI executable; sharing that path with parallel tests running the workspace CLI causes Windows executable-lock failures. Installed tool state and consumer projects remain fresh per test.
